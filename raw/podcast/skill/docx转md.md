# 播客逐字稿整理 Skill

把**任意播客**某一期的原始素材(`_原文.docx`/`_原文.md` 逐字稿 + `_导读.md`)
整理成**一个** Obsidian 友好的合并 markdown 文件。

> 本 skill 与具体播客无关。无人知晓、知行小酒馆及后续新增的播客都按同一套流程与脚本处理。
> 每个播客一个子目录(如 `无人知晓/`、`知行小酒馆/`),skill 本身放在 `podcast/skill/`。

## 目标产物结构

最终每期一个 `E{n} …_原文.md`(文件名不带书名号播客名前缀),层级如下:

```
---
title: E{n} …
podcast: {播客名}
transcribed_at: YYYY-MM-DD
---

> 主播:{主播真名}
> 嘉宾:…

---

# 导读 · 精华解析
## 关键词
## 全文摘要
## 发言总结
## 章节速览          ← 目录,放在「问答回顾」之前
- [[#00:00 标题|00:00 标题]]   ← 每条超链接到正文对应章节
- …
## 问答回顾

# 转录正文
## 00:00 章节标题                    ← 章节(来自导读),二级标题
[[#章节速览|↑ 返回章节速览]]          ← 每章下方回跳目录
> [!QUOTE] 章节概要
> (此处是该章节的一段导读小结)
### {主播} @ 00:16                   ← 说话人锚点,三级标题
你好,欢迎来到……
### {嘉宾} @ 02:28
……
```

### 关键约定(用户确认过的)

1. **标题层级**
   - `# 导读 · 精华解析`、`# 转录正文` 是一级标题;删掉原来的 `# E{n} …` 主标题。
   - 导读内部小节(关键词/全文摘要/发言总结/章节速览/问答回顾)用 `##`。
   - 转录正文里的**章节**(来自导读「章节速览」)用 `## {时间戳} {标题}`。
   - **说话人锚点**用 `### {说话人} @ {时间戳}`,这样能在别的文档里做段落级引用。
2. **导读内容分发进原文**
   - 关键词、全文摘要、发言总结、问答回顾 → 放到文档最前面的 `# 导读 · 精华解析` 下。
   - **章节速览** = 目录,顺序上放在**发言总结之后、问答回顾之前**;每条 `[[#时间戳 标题|时间戳 标题]]` 链接到正文对应章节。
   - 每个「章节速览」条目(如 `00:00 商业分析师…`)按**时间戳**插入到转录正文里对应位置(该章第一段发言之前),并把导读里该章的小结段落一起带过去。
3. **双向跳转**
   - 目录 → 正文:章节速览里的 `[[#…]]` 链接。
   - 正文 → 目录:每个章节标题下的 `[[#章节速览|↑ 返回章节速览]]`。
4. **命名与 title**
   - 文件名和 frontmatter 的 `title` **都不带**书名号播客名前缀(如不要 `《知行小酒馆》`),只从 `E{n} …` 开始。播客名放在 frontmatter 的 `podcast:` 字段里。
5. **章节概要样式**
   - 每章的导读小结段落用 Obsidian callout 包裹:`> [!QUOTE] 章节概要`(米棕色高亮块),紧接在 `↑ 返回章节速览` 之后、第一个说话人锚点之前。

## 处理流程

### 步骤 A:准备 `_原文.md`(逐字稿) — 需要语义理解,手工/LLM 完成

原始逐字稿的说话人是「发言人1 / 发言人2」。要先:

1. **标注真名**:读标题(如「孟岩对话南添」「对话张潇雨」)、开场白与自我介绍,确定每个「发言人N」对应谁。
   - 主播随播客而定:**无人知晓**主播是孟岩;**知行小酒馆**主播是雨白;其他播客读开场白判断。
   - 把 `发言人1 (00:16)` 之类改写成 `**【{真名} @ 00:16】** …`。
2. **转录纠错**:直接修正音转文的明显错字(人名、专有名词、同音词)。
   - ⚠️ **不确定的词保持原样,绝不臆造**。宁可漏改,不可错改。
   - 常见需盯的:嘉宾姓名(易错成同音字)、公司/产品名、书名。
3. 逐字稿每段格式必须是:`**【{说话人} @ {时间戳}】** {正文}`(时间戳支持 `mm:ss` 与 `h:mm:ss`)。

> ⚠️ **时间戳陷阱**:节目常超过 1 小时。做说话人正则替换时,时间戳正则必须能匹配
> `h:mm:ss`(即 `\d{1,2}:\d{2}(?::\d{2})?`),否则 `01:43:10` 会被截断成 `01:43` + 悬空的 `:10`。

### 步骤 B:合并 — 确定性变换,跑脚本

`_导读.md` 里已有:关键词 / 全文摘要 / 章节速览(`- **00:00 标题**` + 小结)/ 发言总结 / 问答回顾。
用 `skill/merge_podcast.py` 自动合并:

```bash
# 指定两个文件
python3 skill/merge_podcast.py "无人知晓/E07 …_原文.md" "无人知晓/E07 …_导读.md"

# 或按集号在某播客目录里自动配对
python3 skill/merge_podcast.py --dir "知行小酒馆" --ep E221
```

脚本会:解析逐字稿的每段发言 → 解析导读各小节 → 按上面的结构重排 →
按时间戳把章节插进正文 → 生成目录与双向链接 → 原地覆盖 `_原文.md` 并留 `.bak` 备份。
脚本逻辑与具体播客无关,任何播客都能用。

### 步骤 C:校验

```bash
f="…_原文.md"
grep -cE "^## [0-9]" "$f"        # 章节数
grep -c "↑ 返回章节速览" "$f"     # 应与章节数相等
grep -cE "^### .+@ " "$f"        # 说话人锚点数
grep -c "发言人" "$f"            # 应为 0
```
再在 Obsidian 里点几个链接确认跳转(标题含中英文冒号 `:`「:」,Obsidian 能正确处理)。

## 批量处理整季

- 逐集执行「步骤 A(人工/LLM)→ 步骤 B(脚本)→ 步骤 C(校验)」。
- 建议先做一集验证结构无误,再批量。
- 缺失的集号(素材不存在)跳过即可。

## 环境注意(本机 Mac / MCP)

- 这些文件在用户真机的 iCloud Obsidian vault 里,只能用 MCP 本地 bash 工具操作。
- **heredoc 与写 `/tmp` 在本机被禁**("Operation not permitted")。写脚本/文件到 Mac 用:
  Write 工具落到沙箱 → 上传到存储 → 在 Mac 上 `curl` 下载到目标目录(用 md5 校验,最稳);或用单引号包裹的 `python3 -c '…'` 就地处理。
- python-docx 已装(读 .docx)。
