> 这份文件是把 2026-08 ~ 09 期间跑通的播客转录流程固化下来的操作规范。
> 第 6 节是**可以整段复制给任意 AI 助手**的 Prompt，把方括号里的内容替换掉即可。

---

# 1. 总流程

```
拿到单集链接/节目名
  → 找到节目 RSS，定位目标单集的音频直链
  → 下载音频（.m4a / .mp3）
  → 上传到转写服务，拿到逐字稿 + 章节 + 关键词 + 摘要
  → 按目标文件夹的既有体例组装 Markdown
  → 写入 Obsidian：yiceng/raw/podcast/<节目名>/<EXX 标题>.md
```

核心原则：**先看目标文件夹里已有的笔记长什么样，再决定新笔记长什么样。** 不同节目文件夹体例不同，不要跨文件夹套用。

---

# 2. 找音频直链

苹果播客链接（`podcasts.apple.com/...?i=<episode_id>`）本身不含音频，需要绕一层：

```bash
# 1) 用 collection id 查 RSS 地址
curl -s "https://itunes.apple.com/lookup?id=<节目数字ID>&country=cn" | python3 -m json.tool | grep feedUrl
# 或者直接按名字搜
curl -s "https://itunes.apple.com/search?term=<节目名>&country=cn&media=podcast&limit=5"

# 2) 从 RSS 里取 <item> 的 <enclosure url="...">
curl -sL "<feedUrl>" -o feed.xml
```

已验证的 RSS：

| 节目 | RSS |
|---|---|
| 夸下海口 | `https://feed.xyzfm.space/9ra7rt9avtl9` |
| 知行小酒馆 | `https://feed.xyzfm.space/j8yp8gxkmgqr` |
| Web3 101 | `https://feeds.fireside.fm/web3101/rss` |

要点：
- 小宇宙系的直链是 `dts-api.xiaoyuzhoufm.com/track/...`，下载时带 `-A "Mozilla/5.0"`。
- RSS 里的 `<itunes:duration>` 就是 `duration` 字段的来源（`01:49:29` → 写作 `1h49min`）。
- 判断「最新一期」「EXX 之后」时，**先列 RSS 前若干条确认编号**，不要凭用户说的期数直接推。

# 3. 转写

用飞书妙记（Lark Minutes）跑，三步：

```bash
lark-cli drive +upload --file <音频路径> --format json          # 取 file_token
lark-cli minutes +upload --file-token <file_token> --format json # 取 minute_token
# 等 4~6 分钟（1~2 小时音频），再拉产物
lark-cli minutes +detail --minute-tokens <token1>,<token2> \
  --transcript --summary --chapter --keyword --overwrite --output-dir ./transcripts --format json
```

产出：
- `transcript.txt`：`Speaker N HH:MM:SS.mmm` + 下一行正文，段落间空行
- `artifacts.keywords` / `artifacts.summary`（结构化大纲）/ `artifacts.chapters`（含 `start_ms` / `title` / `summary_content`）

限制：单文件 ≤ 6 小时、≤ 6 GB；`+detail` 的 stdout 前面有几行日志，解析 JSON 时要从第一个 `{` 开始截。

# 4. 两套体例

## 4.1 A 套 · 机械版（信息密度型节目）

适用：`Web3 101`、技术/资讯类。直接用转写服务的章节标题与摘要，不做二次创作。

```markdown
---
title: E84｜<原始标题>
podcast: Web3 101
transcribed_at: 2026-09-17
---

> 主播:刘峰、Jack
> 嘉宾:美宝

---

# 导读 · 精华解析

## 关键词

<空格分隔，直接用转写服务的关键词>

## 全文摘要

<直接用 AI 的结构化大纲>

## 章节速览

- [[#00:03 章节标题|00:03 章节标题]]

# 转录正文

## 00:03 章节标题

[[#章节速览|↑ 返回章节速览]]

> [!QUOTE] 章节概要
> <该章节的 AI 概要>

### 刘峰 @ 00:03

正文……
```

注意：A 套里 `### 说话人 @ 时间戳` 与正文之间**有空行**。

## 4.2 B 套 · 精编版（人物访谈型节目）

适用：`知行小酒馆`、`无人知晓`、`夸下海口` 等长访谈。必须**通读全文后自己写导读、自己重拟章节标题**。

```markdown
---
title: E249 对话叶檀：我不再是人生的过道人
podcast: 知行小酒馆
guest: 叶檀，财经评论员，新书《与生命和解》
host: 雨白
transcribed_at: 2026-08-30
publish_date: 2026-08-28
duration: 1h36min
source: https://www.xiaoyuzhoufm.com/episode/<id>
---

> 主播：雨白｜嘉宾：叶檀，<一句话身份>

---

# 导读 · 精华解析
## 关键词
<顿号分隔，15~22 个，读完全文后自己判断，不照抄 AI 关键词>

## 全文摘要
<3~4 段散文，每段一个逻辑层次：讲什么 → 论点怎么推进 → 结论落在哪。要有细节和金句>

## 发言总结
- **小标题**：一句话展开（12~18 条）

## 问答回顾（主播 × 嘉宾）
- **Q：……** A：……（10~15 组）
<若本期无嘉宾，改为 `## 核心观点回顾`，同样的 bullet 形式>

## 章节速览
- [[#00:15 章节标题|00:15 章节标题]]

---

# 转录正文

## 00:15 章节标题
[[#章节速览|↑ 返回章节速览]]

### 雨白 @ 00:15
正文……
```

注意：B 套里 `### 说话人 @ 时间戳` 与正文之间**没有空行**。

**章节标题的写法是 B 套的灵魂**，要有画面感、尽量取自嘉宾原话：

- ✅「在别人工具化你之前，你已经先把自己工具化了」
- ✅「衣柜里那排闪闪发光的舞台服，每一件都记得是在哪个机场买的」
- ✅「你买我的股票，你就上市了」
- ❌「叶老师谈从业经历与心态转变」（AI 默认产出的机械标题，不要用）

数量参考：60 分钟 → 15~18 章；90~110 分钟 → 20~26 章。最后一章通常是 `结语 · 雨白的手记`。

# 5. 硬性约束与已知坑

**格式类**
- 章节时间戳**必须恰好等于逐字稿里某一段发言的起始时间**，否则归段会错位。
- 正文文字保持逐字稿原样：不改写、不删减、不合并段落。同音错字（羽白/雨白、方岩/方言、美宝/梅博）只在 frontmatter 和说话人标签上统一为正确写法，正文不动。
- 时间戳格式：不足 1 小时 `46:45`，超过 1 小时 `01:06:04`。
- 章节速览的条目数必须等于正文 `## ` 章节数；正文发言段数必须等于逐字稿里 `Speaker N` 的行数（用这两条做自检）。

**说话人类**
- 说话人映射靠读开场自行判断，不要保留 `Speaker 1`。
- 转写常把主播的某几段误分成多余的说话人（如凭空多出 Speaker 4），按上下文并回去。
- 三人以上对谈要逐个认领身份。

**流程类**
- 组装不要手写，写个小脚本：meta（frontmatter + 章节列表）→ intro（导读三节）→ build 脚本读逐字稿按时间戳归段拼装。多期并行时脚本名带期号前缀，避免互相覆盖。
- 文件名沿用该文件夹的既有习惯：`Web3 101` 用全角竖线 `E84｜标题`，`知行小酒馆` 用空格 `E249 标题`。
- 节目文件夹不存在时按节目名新建。

# 6. 可复制的 Prompt

> 把下面整段发给 AI 助手，替换方括号内容即可。

```text
帮我把播客《[节目名]》的 [EXX] 转录成一篇 Obsidian 笔记。

【第一步 · 拿音频】
先用 iTunes Lookup/Search API 找到该节目的 RSS，再从 RSS 的 <item><enclosure url> 拿音频直链并下载。
下载小宇宙直链时带 User-Agent。同时记下 pubDate 和 itunes:duration。

【第二步 · 转写】
把音频上传到转写服务，拿到逐字稿（带说话人 + 时间戳）、章节、关键词、AI 摘要。

【第三步 · 定体例】
先读 [Obsidian 目标文件夹路径] 里已有的 1~2 篇笔记，严格照它的体例来写，包括 frontmatter 字段、
引言行、章节内链写法、`### 说话人 @ 时间戳` 后面有没有空行。不要自创格式。

【第四步 · 写导读】
如果是人物访谈类节目：你必须完整读一遍逐字稿，然后自己写——
- 关键词 15~22 个（顿号分隔）
- 全文摘要 3~4 段散文，要有细节和金句，不要空洞概括
- 发言总结 12~18 条 bullet，格式 `- **小标题**：一句话`
- 问答回顾 10~15 组，格式 `- **Q：……** A：……`（无嘉宾则改成核心观点回顾）
- 章节标题自己重拟 15~26 个，要有画面感、尽量取自嘉宾原话，
  不要用「某某谈某某与某某」这类机械标题
如果是技术/资讯类节目：直接用转写服务的章节标题和摘要，不做二次创作。

【第五步 · 组装】
写脚本组装，不要手写正文。硬性要求：
1. 章节时间戳必须恰好等于逐字稿里某段发言的起始时间
2. 正文保持逐字稿原样，不改写不删减不合并
3. 说话人映射靠读开场自行判断，多余的说话人按上下文并回主播；
   同音错字只在 frontmatter 和说话人标签上纠正，正文不动
4. 时间戳：不足 1 小时写 46:45，超过 1 小时写 01:06:04
5. 自检：章节速览条目数 = 正文 ## 章节数；正文发言段数 = 逐字稿 Speaker 行数

【产出】
写入 [Obsidian 目标文件夹路径]/[EXX 标题].md，文件名沿用该文件夹的既有命名习惯。
完成后告诉我：文件路径与大小、章节数、发言段数、主播与嘉宾是谁、本期一句话主旨。
```
