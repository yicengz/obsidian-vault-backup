# FDE（Forward Deployed Engineer）在 AI 赛道的角色梳理

> 相关剪藏：[[他的FDE团队从30人扩到100人，但为什么很多大厂工程师甚至不知道这个岗位？]]（课代表立正 × Jove @ Cresta，2026-07-18） 参考：a16z 称其为"科技行业最火的岗位"；2025-04 → 2026-04 相关职位发布量增长约 729%。

## 一、通用定义

FDE 是"嵌入到客户组织内部去干活"的工程师，不是坐在自家办公室写文档 / 做 PPT 的角色，而是直接进到客户的技术与业务环境里（现场 / 混合 / 远程 / 客户 VPC），和客户的领域专家一起工作，写真正跑在客户生产系统里的代码，并**对结果负责到底**。

- 与咨询顾问的区别：顾问交付报告和建议；FDE 把系统搭出来，一直待到它在生产环境真正跑起来。
- 与 Solutions Architect 的区别：SA 主要在售前做设计和 demo，FDE 负责实现和生产交付。
- 起源：军事术语（前线部署部队），Palantir 于 2010 年代初提出。当年背景——情报机构说不清需求、不能共享数据、工作流常变，标准化产品跟不上，只能派工程师驻场。
- 为何在 AI 时代重生：把开箱即用的 LLM 变成贴合企业业务的 agentic workflow，中间工作量巨大（幻觉、延迟、RAG、eval、guardrail），demo 惊艳但落地是另一回事。OpenAI / Anthropic / Google 都在大量招。
- 能力画像：软件 + 销售 + 平台工程的混合体，客户面对面时间占比高（25–80%，远高于普通产品工程师的 10–20%）。
- 冷静判断（吴恩达）：FDE 很热，但一家公司只接受少数几个嵌入，AI Engineer 的岗位总量会远大于 FDE。

## 二、Jove（Cresta，语音 AI）访谈中的一线视角

**1. FDE 必须绑定 AI Agent 语境。** 只做数据 ETL / 搭网络这类传统活，FDE 和驻场 / 外包 / 咨询没本质区别；只有绑在"客户想要 AI Agent 但自己搞不定幻觉、RAG 延迟、guardrail、eval"的场景，AI Agent FDE 才是"新物种"。核心优势是 AI native——模型和 feature 大家都能拿到，但做好差距极大。

**2. 招什么人 / 为什么难招。** 现在不敢招 junior；要求 3 年以上、本身是好 engineer，最好有 co-founder / founding engineer 经历（尤其创业失败、特别是 AI 创业失败的人），或 consulting / customer-facing 背景。吐槽："我会用 Claude Code"已等于"精通 Excel"，必须真做过 AI Agent（LangChain / RAG / 尤其 voice）才算数。

**3. 组织架构。** Cresta 把 FDE 放在 product engineering 里（不是 customer success / professional service / 售前）。仿 Palantir 双队模式：偏工程的 FDE + 偏 business 的 FDPM（forward deployed product manager）。FDE 不只驻场，还回头改自家平台的 REST API / 微服务 / UI / CLI / 文档，目标是把简单 case 自动化、逼自己啃更难的领域专精。

**4. 信任比技术更难。** 技术落地看得见，但背后的 trust 是长期积累——Cresta 拿下 Marriott、United 靠多年声誉 + 合规工作；成立几周的创业公司很难让 CEO/CTO 拿职业声誉赌你。因此不看好"很会写代码的一人公司单干转 FDE"。

**5. 名词 vs 动词。** 模型名、feature 这些"名词"有限，10 分钟能学一个；功夫全在"动词"里——routing、resolve 怎么做好、何时给模型什么 skill、恰当时候喂对 context，深不见底，不做不知道。

**6. 从"为 skill 负责"到"为结果负责"。** skill 正被 AI 大规模取代，但 AI 没法为结果担责（换个 prompt 就变一句话）；越靠近结果越难被取代。FDE 因此是个"避风港"，里面有大量"人"的成分。

**7. 其它要点。**

- Voice AI 是 top-3 AI 应用（另两个：coding、multimedia 生成）。Cresta 做 call center / customer experience，也做牙医、酒店、餐馆的 AI receptionist。
- FDE 是"last mile"角色，会随技术演进（A2A、具身智能）但人仍需补最后一公里。
- 商业模式：outcome-based 定价 + ARR/SaaS 订阅；模型迭代快，客户需持续 engage，不是一枪头买卖。
- 咖啡师 / omakase 类比：模型（豆子）易得，做出好 outcome 很难。
- AI 产品 6 层次：prompt wrapper → grounded AI → tool-using AI → LLM workflow → agentic core → AI native product；Cresta 语音客服的 candidate 到 level 4 即可。
- 面试环节：不用 AI 写简单 Python（证明工程素养）→ engineering practice 轮 → 90 分钟基于给定 API/KB 用 Claude Code/Cursor 现场搭 agent（含 test/eval、edge case）→ behavior 轮 + 与 FDPM 配合度。
- win trust 特质：愿 listen + 站对方角度；EGO 小（为把事做成而非证明自己对）；technically solid。Red flag：一个问题答 6–10 分钟。

## 三、和我（数仓 / 国内 / ByteDance）相关的判断

访谈末尾专门聊国内前景，Jove 观点是"橘子种哪里很关键"：

- 北美人工贵、愿为结果买单、SaaS 成熟 → AI Agent FDE 容易落地。
- 国内人工没那么贵、ToB 市场 tricky、SaaS 问题多（他直言最核心问题是没有真正的 enterprise 市场和大客户）→ FDE 模型"还很难讲、可能太早"。国内群里分歧大，有唱衰也有觉得迟早会到。
- 他也提到：数据库实施、数据清理、政务这类复杂形式，并不适合套 FDE 模式。

> 个人延伸思考（待补）：数仓驻场"帮业务把数据体系搭起来、对能不能用负责"与 FDE 有相通处，区别是对象换成 LLM/agent、更偏对外客户交付。国内环境下，这种能力更可能以内部角色而非独立 FDE 岗位形式存在。
