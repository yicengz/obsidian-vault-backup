# bill-sync skill 搭建记录

## 起因

以前每次记账，都是导出支付宝 CSV 和微信 XLSX 之后，把文件丢给 Claude，附一大段提示词让它按飞书多维表格的列结构整理。规则和上下文没有持久化，每次都是冷启动——Claude 要重新推理"魔盒CITYBOX=公司饮料柜"、"亲情卡剔除"、"红包发给莫菲=苏河湾停车"这些映射，还容易漂移。

这次干脆封成一个 skill，规则外置，一句话触发。

## 关键路径

- Skill 定义: `~/.claude/skills/bill-sync/SKILL.md`
- 脚本目录: `~/program/bill-sync/`
  - `process.py` — 主入口
  - `parsers.py` — 支付宝 GBK CSV + 微信 XLSX 解析
  - `rules.yaml` — 分类规则（可直接编辑）
- 账单源: `~/Downloads` 和 `~/Desktop`（两个目录都扫，取最新的一份）
  - 支付宝: `alipay_record_*.csv`
  - 微信: `微信支付账单流水文件*.xlsx`
- 输出: `~/Desktop/账单整理_YYYYMMDD.tsv`（Tab 分隔，13 列，无表头）

## 默认使用方式

跟 Claude 说"整理下账单"、"同步账单"、"处理支付宝账单"这类话，它会自动触发 skill。

手动跑的话：

```bash
python3 ~/program/bill-sync/process.py --auto
```

会输出一份 JSON，里面有已识别的行、未识别的条目、和统计信息。

## 分层设计

三层：

1. **确定性层（Python + YAML）**：解析文件、剔除条目、退款回写、商户映射。规则全在 `rules.yaml` 里。
2. **判断层（LLM）**：Python 落空的商户放进 `unknown_entries`，Claude 现场判断。有意识地**不写回 yaml**——保持规则文件精简可读，靠 LLM 兜底。
3. **组装层（Claude）**：合并两部分行 → 时间倒序 → 写桌面 TSV。

## rules.yaml 三种规则

匹配顺序：`skip` → `special` → `merchants` → 落空进 unknown。

### skip（剔除）

- 支付宝：亲情卡、珏珏子(其实就是亲情卡对手方)、不计收支、收入、余利宝转账、零元记录（比如医保支付 0 元）
- 微信：亲属卡交易、收入、群收款支出、退款条目（退款金额已从原单的"成功退款"或"已退款(¥X)"字段回写）

### special（优先匹配的条件规则）

- 微信红包发给莫菲 → 苏河湾停车
- 微信扫码到"苏河湾万象天地" → 苏河湾停车
- 其他红包兜底 → 人情往来/请客
- 转账支出兜底 → 人情往来/请客

### merchants（关键字命中即分类）

按大类组织，比如：

```yaml
- match: [魔盒CITYBOX, 友宝, 上海博申自动售货机, 上海百纶集科技发展]
  row: {说明: 公司饮料柜, 大类: 基本饮食, 小类: 零嘴, 细分类: 饮品}

- match: [绿城物业]
  row: {说明: 物业费, payer: 双人行, 大类: 基本生活, 小类: 物业, 细分类: 物业费, 刚性: 是}
```

`row` 里能用 `{keyword}`（命中的关键字）和 `{counterparty}`（原交易对方）做变量替换。

## 触发流程（Claude 视角）

```
用户："整理下账单"
  ↓
Claude 匹配 skill: bill-sync
  ↓
跑 python3 ~/program/bill-sync/process.py --auto
  ↓
拿到 JSON：{matched_rows: [...], unknown_entries: [...], stats: {...}}
  ↓
Claude 遍历 unknown_entries，参考 SKILL.md 里的"分类学速查"逐条判断
  ↓
合并 matched + 补齐行 → 时间倒序 → 写 ~/Desktop/账单整理_YYYYMMDD.tsv
  ↓
汇报：总数/剔除/已识别/退款回写/现场判断
  ↓
我复制粘贴到飞书多维表格
```

## 首次跑的结果（作为回归基准）

用 2026-05-01 到 2026-07-04 的账单验证：

- 支付宝原始 445 条 + 微信原始 201 条 = 646 条
- 剔除 309（亲情/亲属卡、收入、退款条目、零元、余利宝）
- 已识别 285（规则命中）
- 现场判断 52（外卖、香烟、境外消费、抖音代金券、扫码摊贩、马来西亚旅行）
- 退款回写 1（盖帮主 3.9 元）
- **最终输出 337 条**，跟之前手工整理版本的合计完全一致

只有 2 条"账户通付款"（别人使用了我的账户通）大类留空，需要我自己核对——因为不知道对方买了啥。

## 想加新商户怎么办

直接编辑 `~/program/bill-sync/rules.yaml`，在 `merchants:` 下加一行：

```yaml
- match: [美心月饼]
  row: {说明: 月饼, 大类: 购物消费, 小类: 小件}
```

下次跑就命中，不再进 unknown。

**明确不做的事**：不让 Claude 现场判断的商户自动写回 yaml。我更希望规则文件是"我审慎沉淀的东西"，不是"被 Claude 一次判断就污染的东西"。规则精简，反倒逼着我自己想清楚——哪些商户值得沉淀成规则，哪些是一次性的。
