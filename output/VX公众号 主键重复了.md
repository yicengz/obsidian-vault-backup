# 前言：连着2天凌晨5点告警

前两周，上游的核心维度表出现了主键重复，并且发生了两天

作为下游，我连着两天凌晨5点起来修复数据，导致睡眠大打折扣
【插入Apple健康截图】

处理问题的时候我就在想，上游为什么会出现看似低级错误的现象，因为认真做过数仓其实能明白，现实往往比理论复杂得多。

趁着周末有时间简单聊聊

# 1. 冷热分治的设计初衷 vs 现实裂缝

问题出在一张百亿级的维度视图上。
为了兼顾查询便利性与存储成本，上游对视图背后的物理表，采用了**冷热数据分离策略**：

以下是视图的执行逻辑
``` sql
-- 热数据-近180天
SELECT id FROM db.dim_table
WHERE dt = '${bizdate}' AND range = 'inner180d'

UNION ALL

-- 冷数据-180天以前
SELECT id FROM db.dim_table
WHERE dt = '${bizdate}' AND range = 'outer180d'
```

按业务逻辑，每个 ID 的 `create_time` 决定了它只属于“热”或“冷”中的一个分区——理论上，不可能同时出现在两个子查询中。

但那天，上游后端在写入时传入了一串格式异常的 JSON，导致我们在解析时误判了部分记录的创建时间。结果，**近20个 ID 同时落入了 `inner180d` 和 `outer180d` 两个分区**。

而这两个分区由两个独立的数仓任务写入，各自都配置了主键重复监控，单独看完全“合规”。
但若通过 `UNION ALL` 合并成视图，重复ID就会被读取到

**局部正确，全局却错了**——这正是分布式系统中最隐蔽的陷阱。

# 2. 故障的涟漪效应——从当天蔓延到次日

其实，如果只是当天数据有点重复，或许还能接受。但问题在于，**并非所有任务都配置了拦截机制**。

视图本身不做去重，下游某些任务又缺乏强校验逻辑，导致错误数据被当作“正常产出”继续流转。更糟的是，部分依赖链路没有设置失败熔断，使得第二天的任务也基于前一天的脏数据运行，雪球滚得不大，但滚到了第二天的我身上。

那天我就睡了4h左右，等到了晚上下班到家躺在床上反而睡不着的时候，我其实挺崩溃的。

# 3. 因祸得福——一次故障换来的业务共识

不过，坏事有时也能变好事。

就在故障前几天，我正和一个 C 端业务方“拉扯”：他们希望每天上午 10 点就能将数据透出给C端用户，而我们的 SLA 是中午 12 点甚至 14 点。他们反复质疑：“为什么不能早点？数据不是跑完就行了吗？”

我当时没多解释，只说：“我们要保证质量，不能为了快而牺牲准确性。”

结果，主键重复导致大面积延迟的那两天，他也终于理解我说的自身无力解决的局面，并最终接受了14点SLA的方案。

**做幕后基建类的工作，有时候一次真实的故障，比十次宣讲更有说服力**。它让业务真正理解了“稳定”和“准确”背后的代价

# 草稿
> 

前两周，有3天凌晨起来修数，其中两天是直接因为上游的核心表ID重复了

上游是一张维度视图，数据量百亿起步。背后的两张表分别存了热数据近N天，冷数据N天以外

``` sql
select id
from   db.dim_table
where  dt = '${bizdate}'    -- 一级分区
and    range = 'inner180d'  -- 根据业务上的创建日期: create_time来判断

union all

select id
from   db.dim_table
where  dt = '${bizdate}'    -- 一级分区
and    range = 'outer180d'  -- 根据业务上的创建日期: create_time来判断
```

理论上一个ID不会涉及两个日期
但那天在上游的后端侧，有一串Json里参数有问题，导致数仓在解析的时候，有近20个id再union all的两段逻辑里都被获取到了

'inner180d'和'outer180d'两个二级分区，分别对应两个写入任务，并且对各自的分区有主键重复的监控

因此在这个偶发情况下，导致视图查出来的结果出现了主键重复，并且向下游放行

其实我自己觉得也谈不上多要命的，我觉得同为数仓很能理解。但对我来说也比较难受，当天的数据重复甚至波及到了第二天，因为有些任务没有被拦截到位。

最近我自己也在考虑对数据进行冷热分治，想借鉴参考上游的这个操作。但除了这个问题后再结合Q1的有限精力，优先级还是可以先往后放一放。

不过，有另外一个需求倒是因为这次主键重复而因祸得福。一个面向C端的数据总结需求，业务反复质疑为什么数据非要保障到12:00甚至14:00。过了几天就出现了主键ID导致产出大面积延迟的问题，他就答应了我的提议。
